# menu_analysis/ ディレクトリについて

「ラーメン」「ランチ分析」「アルコール」の3ページが使うデータ加工ロジックです。

## なぜこんなに階層が深いのか

このお店は2026年6月1日にPOS（レジ）システムを切り替えました。そのせいで、**同じ「白味噌ラーメン」でも、日付によって記録のされ方が全然違います**。

| | 〜2026年5月31日（旧データ） | 2026年6月1日〜（新データ） |
|---|---|---|
| データの形 | 商品名ごとに列が並ぶ「横持ち」の日次集計 | 1明細＝1行の生の取引データ |
| 時間帯の分かり方 | 商品名自体が昼用/夜用/深夜用で別名になっている | 会計時刻を見て判定する |

この2つを**同じ「白味噌」というカテゴリとして1つのグラフに合体させる**ために、5段階のパイプラインを組んでいます。`menu.json`（`data/json/menu.json`）が「新旧どちらの商品名でも、このカテゴリに属する」という対応表の役割を果たします。

## 5段階のパイプライン

```
①生データ取得(s1_data_sources)
        │
        ▼
②商品名→カテゴリ名の分類(s2_classification) ← menu.jsonを読む。新旧共通で使われる
        │
        ▼
③新データ側だけの時間帯別集計(s3_transaction)
        │
        ▼
④新旧データの合体(s4_facades)
        │
        ▼
⑤グラフ用に1つのDataFrameへ整形(s5_formatting)
        │
        ▼
   ../../charts/menu_analysis/ で描画
```

### ① `s1_data_sources/` — 生データの読み込み

| ファイル | 何をするか |
|---|---|
| `LoaderBefore202606.py` | 旧データ（Googleスプレッドシート「シート1」、2026年6月より前）を全期間分取得する |
| `LoaderAfter202606.py` | 新データ（Googleスプレッドシート「会計別_全期間まとめ」、2026年6月以降）を取得する。旧データと同じく、誰かがAirレジの会計別データをこのシートに反映してくれる前提で、アプリ側は読みに行くだけ |

### ② `s2_classification/` — 商品名をカテゴリに分類する（新旧共通）

`menu.json`はこんな形をしています。

```json
{
  "白味噌": {
    "flag": ["1"],
    "item": ["白(ノーマル)", "白味噌ラーメン(ノーマル)", "白味噌(煮卵付き)", ...]
  }
}
```

- `item`：このカテゴリに属する生の商品名を、新旧問わず全部並べたもの
- `flag`：このカテゴリの種類を表すコード（下の表）

| flag | 意味 |
|---|---|
| `1` | ラーメン |
| `2` | セット |
| `3` | その他フード |
| `4` | アルコール |
| `4.1` | └ ビール系（`4`と併記） |
| `4.2` | └ 秋鹿系（日本酒、`4`と併記） |
| `4.3` | └ ワイン系（`4`と併記） |

| ファイル | 何をするか |
|---|---|
| `TransactionCategoryMap.py` | 新データの「商品名＋バリエーション」から、`menu.json`を引いてカテゴリ名を求める |
| `CategoryUnifyMap.py` | `menu.json`の`flag`を管理する。「このカテゴリはラーメン？」「アルコールのカテゴリ一覧をちょうだい」に答える |
| `TimeSlotClassifier.py` | 会計時刻から「昼/サンセット/夜/深夜」を判定する |
| `TransactionAggregator.py` | 日付×商品名でピボット集計する共通処理 |

**このフォルダのポイント：新しいメニューが増えても、ここのPythonコードは変更不要です。`menu.json`（スプレッドシートから書き出す運用）を更新するだけで反映されます。**

### ③ `s3_transaction/` — 新データだけを集計する

| ファイル | 何をするか |
|---|---|
| `RamenTransactionUtils.py` | 新データから、昼/夜/深夜ごとのカテゴリ別売上dictを作る |
| `AlcoholTransactionUtils.py` | 新データから、アルコールのカテゴリ別売上dictを作る（時間帯フィルタなし） |
| `FacadeMergeUtils.py` | 「2026-06-01より前/以降」でデータを分割する処理と、新旧を1つに結合する処理 |

### ④ `s4_facades/` — 新旧データを合体させる

| ファイル | 何をするか |
|---|---|
| `AnalysisFacades.py` | `RamenAnalysisFacade`/`LunchAnalysisFacade`/`AlcoholAnalysisFacade`の3クラス。旧データ（①②経由）と新データ（③経由）をカテゴリ名で紐付けて1つのDataFrameに合体させる。**`pages/analytics.py`が直接呼ぶのはこの層まで** |

### ⑤ `s5_formatting/` — グラフに渡す形へ整形する

| ファイル | 何をするか |
|---|---|
| `LunchAnalysisUtils.py` / `DinerAnalysisUtils.py` / `MidnightAnalysisUtils.py` | ④が返した「カテゴリ名→DataFrame」の辞書から、ラーメン系だけ合計して1つのDataFrameにする（昼/夜/深夜それぞれ用） |
| `AlcoholAnalysisUtils.py` | 同様にアルコール全体を集計し、ビール/秋鹿/ワインへの絞り込みも行う |

## 具体例で追ってみる

「2026年5月の白味噌ラーメンの深夜売上」がグラフに出るまで：

1. `s1`: `LoaderBefore202606`がGoogleスプレッドシートから2026年5月分を含む全期間データを取得
2. `s2`: `CategoryUnifyMap`が`menu.json`を見て、旧商品名`白(ノーマル)`も`白味噌`カテゴリだと判定
3. `s4`: `RamenAnalysisFacade`が「2026-06-01より前」の`白味噌`列を、新データ側の`白味噌`と同じキーとしてマージ用意（この時点では新データ側は空、まだ6月になっていないため）
4. `s5`: `MidnightAnalysisUtils`が深夜カテゴリ全体を1つのDataFrameに集計
5. `charts/menu_analysis/RamenAnalysisCharts.py`が円グラフ・棒グラフとして描画

## 迷ったときは

- 「新しいメニューを追加したい」→ コードは触らず`menu.json`（元はスプレッドシート）を更新するだけでOK
- 「このカテゴリだけグラフに出したい/出したくない」→ それは分類ではなく**表示の都合**なので、`s4_facades/AnalysisFacades.py`か`../../charts/menu_analysis/`側の話
- 「新旧のカテゴリ名がズレてグラフから消えた」→ `menu.json`の`item`にその商品名が正しく登録されているか確認
