# AIに聞く：処理フロー

自然言語の質問 → 適したグラフを選んで表示 → 重要な部分を強調

- 判断（どのグラフか・どの引数か）: **Jev**
- 計算・集計・描画: **コード**
- 低 confidence・対応外: **安価な LLM**（ツールコーリング）

詳細設計: `design.md`

---

# 全体像

| ① 前処理 | → | ② 判断 | → | ③ 分岐 | → | ④ 実行 | → | ⑤ 表示 |
|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| 期間を解釈 | | Jev に質問 | | confidence で振り分け | | データ取得・強調候補を算出 | | 強調つきで描画 |
| **コード** | | **Jev** | | **コード** | | **コード** | | **チャート** |

---

# ① 前処理：期間の解釈（コード）

Jev は日付が苦手なので、Jev に渡す前にコードで解釈する。

| 質問の表現 | 変換結果 |
|---|---|
| 先月 | 2026年9月 |
| 去年の夏 | 2025年6〜8月 |
| 今年 | 2026年1月〜最新月 |
| （指定なし） | 最新月 |

月の候補は件数が多く、Jev は先頭の選択肢に偏るため、Jev には選ばせない。

---

# ② 判断：Jev に並列で質問

同じ質問文に対する独立した質問を **1リクエスト** で投げる。

| 質問 | 種類 | 内容 |
|---|---|---|
| 答えられるか | Noul | データで答えられる質問か |
| どのグラフか | Choice | チャートカタログの ID |
| 引数 | Choice | 指標・時間帯・モード・曜日など |
| 何を強調するか | Choice | 最大 / 最小 / 変化が大きい点 / なし |

セッション内の直前の指定（`previous_request`）があれば state に含める。

---

# ③ 分岐：confidence で振り分け

```
答えられる確率が低い ─────────────→ 「対応外です」と返す
        │
        ▼
最も弱い質問の confidence

   高  (≥0.8)  → そのまま実行
   中  (0.5〜) → 「〇〇の意味ですか？」と聞き返す
   低  (<0.5)  → 安価な LLM にフォールバック
```

しきい値は仮置き。日本語の質問サンプルで実測して決める。

---

# ④ 実行：コードがデータを作る

- チャートカタログの `render` に必要なデータを取得（既存の Utils / Facade）
- 集計して**強調の候補を算出**する
  - 最大値・最小値
  - 前期比の変化が最大の点
  - 外れ値
- Jev が選んだ強調タイプに合わせて、対象を1つに決める

Jev に強調箇所そのものを生成させない。**候補はコードが出し、Jev は種類を選ぶだけ。**

---

# ⑤ 表示：強調のしかた

配色がチャートごとに違っても目立つように、色ではなく見せ方で強調する。

- 対象以外を薄くする（透明度を下げる / 灰色に寄せる）
- 対象は元の色のまま残し、値のラベルを付ける
- 円グラフは対象のスライスを少し切り離す
- 月別・年間は既存の「最新の1本だけオレンジ」に揃える

---

# 例：「先月のランチでよく出たラーメンは？」

| 段階 | 結果（数値は仮） |
|---|---|
| ① 前処理 | 先月 = 2026年9月 |
| ② 判断 | 答えられる 0.97 / `lunch_pie` 0.91 / モード=販売数 0.88 / 強調=最大 0.82 |
| ③ 分岐 | 最小 0.82 ≥ 0.8 → 実行 |
| ④ 実行 | 9月の昼ラーメンを販売数で集計、最大のカテゴリを特定 |
| ⑤ 表示 | 円グラフで最大のカテゴリだけ色を残し、他を薄く |

---

# フォールバックの流れ

```
Jev の confidence が低い / 対応外と判定
        │
        ▼
安価な LLM（Gemini / GPT-5.6 Luna）
  ・チャートカタログをツール定義として渡す
  ・ツールコーリングで chart_id と引数を返させる
        │
        ▼
カタログの検証（存在しない ID・範囲外の引数は弾く）
        │
        ▼
通常フローの ④ へ
```

LLM の出力も、カタログの検証を通ったものだけを実行する。
